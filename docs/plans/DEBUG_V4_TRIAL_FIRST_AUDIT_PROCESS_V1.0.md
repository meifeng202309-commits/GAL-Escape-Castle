## 1. 最高目标与边界

唯一近期最高优先目标：**尽快开展下一轮真实 Teacher + 3 Players 的 ACT1–ACT14 全流程试玩，收集实际阻断问题。**

本项目为封闭教学使用、匿名玩家、非商业游戏。审计的成本必须与风险的实际教学影响相称。以能玩、能发现真实问题、能恢复试玩为第一准则，而不是“所有边缘情况全部有证明”。

本计划改变 CA 的审核**优先级、要求和节奏**，不自动授予数据库写入、网页发布或其他 Agent 受保护资源写入权限；不能据此重复使用已消耗的一次性生产授权。不得绕过平台/工具权限要求。

## 2. 三等级问题处置

- **P0 — 立即修复 / 阻断试玩**：无法进入或继续 ACT、3 人流程卡死；数据大量丢失/错误覆盖；错误玩家身份/私密信息跨人暴露；状态推进明显错误；无法恢复教学游戏。只检查与本次试玩直接相关的客观证据。
- **P1 — 试玩中观察 / 可简单修**：按钮重复、部分提示不准确、局部展示故障、偶发重试问题；只有明显低成本改动且能减少试玩失败时才在试玩前处理。否则记入发现表，待 Teacher 实测决定。
- **P2 — 暂不处理**：低概率、实际影响小且开发/审计成本大的问题；装饰、音效细节、广义安全加固、非必要架构优化、完整 TOP 边界、所有历史字段治理。记录最小事实，不自动新增代码或阻断试玩。

任何问题都应标出：可复现性、受影响 ACT、实际后果、是否有简单绕行、预计修复/验证成本。没有实际失败证据不得仅凭推测升级为 P0。

## 3. 对原 V4 工作安排的变化

### 现在执行的最短路径 (Lane N, Trial-First)

1. **最小试跑前检查（一次合并批次）**：当前页面可访问；Teacher 创建房间；3 人匿名加入；正式 Start；关键连接有效；有明确恢复/停止方式；确认没有其他正在使用的课堂房间。保留旧数据、不清理历史记录。
2. **选用最短可运行路径**：优先使用当前已部署的安全可用版本直接开展诊断性 ACT1–14 试玩；针对首次真正阻断进行定向修复。已准备但尚未发布的 069 B-min、070 W03、071 ACT7 不得笼统标为“必须全部先部署”。
3. 如果目前已证实的 P0 使目标 ACT 无法继续，才部署对应最小改动；限当次必需代码/SQL，简单回退点和即时 smoke 即可。生产修改需另有明确授权。
4. **全流程诊断试玩**：Teacher + 3 Players；逐 ACT 记录 PASS / BLOCKED / BYPASS / NOT_REACHED，第一处 P0 收集截图、ACT、角色、操作及时间；有可用且不会污染关键行为证据的简单手动推进时可继续诊断，否则停止并按影响排序修复。
5. 完成一次试玩后由 Teacher 决定 P1/P2 是否值得修复，不允许自动从问题列表生成大量新任务。

### 暂缓而不是废弃

- Lane R ACT1–14 全边界 TOP 自动恢复；全套行为证据精细化；大规模字段 Authority 清理；音效/占位图美化；额外防护框架；没有明确阻断证据的网络/会话极端恢复测试。
- 071 的复杂一次性迁移演练不得继续成为 ACT1–14 **诊断试玩**的全局入口条件。若 Teacher 确认该项确为实际 P0，再按最小可执行方式单独处理。
- A1/B/W03 已完成的源码不废弃，但只对实际障碍按依赖顺序启用。

## 4. 新 Audit 规则（取代本计划范围内的过度要求）

- **一次代码包一次集中审核**：CD 提供变更路径、主要功能、可重复的最小测试与回退方式。CA 只核对对应 P0 / 高影响回归；不再把每个细节拆成多轮审计信。
- **审计预算**：每轮最多提出 3 个实质性阻断项；低影响发现列入 backlog，不阻断下一轮试玩。确需超过 3 个时解释现实危险和成本。
- **轻量测试**：最小静态/语法检查、一个正向路径、一个相关失败路径；不为低概率可能性增加新模块、全局日志、跨工具证明链或独立基础设施。
- **现有治理保底**：保持玩家身份隔离、真实行为不伪造、未经批准不修改生产数据、不删除历史数据、保留简单恢复方案。可减轻繁琐文档和重复确认，不能取消必要的写入权限和事故边界。
- **handoff 合并**：单封 CA→CD 明确要解决的 P0、允许改动边界、测试、结束标准；CD 直接工作至完整包；CA 单次审计再移交。GA 只在真实玩法语义争议需要裁决时参与；ISA/TCA 不作 FYI 抄送。
- **实际试玩优先**：只要满足“能开始、能观察、可停止和恢复”，不要等待生产级完整验收；诊断试玩不是最终正式发布或行为科学数据认可。
- **STOP 准则**：严重数据库异常、错误身份/隐私泄露、不可恢复流程、回退不明确时 STOP；一般文本/视觉/偶发低影响 bug 不 STOP，记录后继续。

## 6. 简明交付 / 衡量

CD 提供一页以内 Trial Readiness 表：
- 当前部署版本及入口；
- ACT1–14 当前可达性：已实证 / 未实证 / 已知阻断；
- 需要在试玩前处理的 P0（最多 3 项）；
- 教师必须做的最少操作；
- 计划试玩步骤与失败记录方式。

CA 按“下一轮完整试玩是否可以现在开始？”回答 YES / YES WITH KNOWN LIMITATIONS / NO (P0 evidence)。不给未经证实的进度百分比；以完成实际 ACT 场景数量、阻断解除速度和审核轮次记录绩效。

适用：自本计划批准并入库后所有下一轮 Debug Implementation Plan 审计；与现行规范冲突时，具体生产授权/身份与数据保护等硬性要求仍有效；其他低风险 audit 要求以本计划的比例原则为准。
