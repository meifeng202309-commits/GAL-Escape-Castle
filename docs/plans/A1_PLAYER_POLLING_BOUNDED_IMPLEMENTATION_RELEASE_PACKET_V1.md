## 1. Requested bounded release

Authorize only A1 Player polling correctness. This packet does not authorize Teacher polling, rendering redesign, database changes, Supabase mutation, asset publication, deployment or any later package.

Goal: prevent overlapping Player refreshes, stale-session DOM commits and transient read failures being rendered as game inactivity, while preserving current gameplay ownership and presentation.

## 3. Confirmed defect mechanism

`src/game/app.js` currently:

- starts `setInterval(refreshState, 1200)` without waiting for the prior refresh;
- performs a sequence of RPC reads that may exceed 1.2 seconds;
- guards only some stages with `session!==activeSession`;
- converts several Sprint5/Sprint6/Sprint8 read failures into `{active:false}`;
- can therefore let transport failure or an older request select an inactive/pre-run/wrong-domain rendering path;
- lets mutation-triggered `await refreshState()` overlap the timer refresh.

No database change is needed to prevent those client-side races.

## 5. Implementation contract

Implement the coordinator inside `src/game/app.js`; do not add a general polling framework.

### 5.1 Scheduling

1. Replace the repeating interval with a one-shot timer scheduled only after the current refresh settles.
2. Maintain one Player refresh in flight at a time.
3. Maintain a session epoch incremented on join, leave and replacement/rejoin.
4. Maintain a monotonic refresh generation within the epoch.
5. A timer/manual/mutation request arriving during an in-flight refresh queues at most one follow-up refresh.
6. The promise returned to a mutation caller resolves only after a refresh at or after that request has settled; it must not falsely resolve on the older in-flight frame.
7. `stopPolling()` clears the one-shot timer, queued work and invalidates the epoch so a late response cannot commit.
8. Preserve the nominal 1.2-second delay between completed passive polls; do not attempt to catch up missed ticks.

### 5.2 Read classification

Distinguish:

```text
SUCCESS(payload)
NOT_APPLICABLE(payload.active === false from a successful RPC)
FETCH_ERROR(error)
INVARIANT_BREACH(reason)
```

A rejected/failed RPC must not be rewritten as `{active:false}`. Optional-domain inactivity is accepted only from a successful RPC response. Authentication/session-invalid responses may return the user to join only through their explicit existing session contract, not through a generic network-error path.

### 5.3 Candidate frame and commit

1. Capture the session object, epoch and generation before reads.
2. Read the existing lifecycle projections in the existing precedence: completed S8 before active S2, then the active domain projections.
3. Assemble the lifecycle/domain decision before committing the corresponding root view.
4. Before commit, require the same session object, epoch and current generation.
5. Discard a stale candidate silently; it may not clear or replace the current confirmed view.
6. On transient fetch failure, preserve the last confirmed passive frame and show a panel-local stale/error indication.
7. Disable only mutation controls whose exact current identity cannot be verified; do not claim that the run is inactive.
8. Keep existing S8-before-S2, ACT5 handoff and ACT6 entry-barrier precedence unchanged.

This package may factor small local helper functions inside `app.js`, but it must not rewrite renderers or introduce a second state store.

### 5.4 Mutation-triggered refresh

- Existing mutation request UUID behavior remains unchanged.
- A successful mutation requests one immediate coordinated refresh.
- An unknown acknowledgement keeps the existing request UUID and does not create a new mutation attempt.
- A failed refresh after a successful mutation does not reissue the mutation.

## 6. Exact tests

### 6.1 Static test — `tests/a1-player-polling-static-check.js`

Require:

- no `setInterval(refreshState, 1200)` or equivalent overlapping interval;
- one-shot rescheduling occurs after settlement;
- explicit in-flight, queued, epoch and generation guards exist;
- leave/rejoin invalidates prior work;
- no `.catch(()=>({active:false}))`-style transport-to-inactive conversion remains for lifecycle/domain reads;
- completed-run lookup still precedes active-run dispatch;
- existing ACT5/ACT6 lifecycle dispatch markers remain;
- no Teacher/SQL/asset file is part of the A1 implementation diff.

### 6.2 Deterministic browser test — `tests/a1-player-polling-browser.mjs`

Use an isolated local page and intercepted RPC responses; no live database mutation.

Scenarios:

1. hold a read beyond 1.2 seconds and prove maximum concurrent Player refresh count is one;
2. request an immediate mutation refresh during the held poll and prove exactly one follow-up occurs;
3. release an old response after leave/rejoin and prove it cannot alter the new session view;
4. fail one optional-domain transport request and prove the last confirmed frame remains instead of pre-run/inactive fallback;
5. return a successful `{active:false}` and prove legitimate NOT_APPLICABLE handling still works;
6. delay completed/active lifecycle reads and prove S8 completion precedence remains stable;
7. stop polling and prove no later timer or held response commits;
8. verify no uncaught browser exception and no duplicate mutation request.

## 7. Acceptance criteria

- maximum one in-flight Player refresh;
- queued immediate refresh is neither lost nor duplicated;
- stale epoch/generation never commits;
- transport failure never masquerades as `active:false`;
- last confirmed passive frame survives transient failure;
- session replacement invalidates late work;
- existing lifecycle precedence and mutation idempotency remain intact;
- all listed static/browser regressions pass;
- diff contains only the allowed files.

## 8. Rollback

A1 has no schema or stored-data migration. Rollback is one code revert restoring the prior `src/game/app.js` blob and removing/retaining only non-runtime tests as agreed. Verify after rollback:

- the prior page loads;
- join/leave works;
- no orphan timer from the reverted build survives a reload;
- server data and request receipts require no repair.

Because rollback restores the known overlapping interval defect, it is an emergency fallback, not an acceptable final state.

## 9. STOP conditions

Stop without expanding scope if:

- runtime code baseline differs materially from the hashes above;
- implementation requires any SQL/RPC signature or Teacher polling change;
- correct coordination requires changing gameplay authority or renderer semantics;
- a failed read cannot be distinguished from legitimate inactivity using current RPC success/error behavior;
- mutation callers cannot receive an after-request refresh guarantee without changing request identity semantics;
- existing structural/S8/placeholder tests regress;
- deterministic browser test cannot reproduce and prove the race boundary;
- unrelated user changes overlap an allowed file.
