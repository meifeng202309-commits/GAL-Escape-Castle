## 2. Chrome hidden/background throttling

| Classification | Project evidence | External evidence and limit | Recommended next action |
|---|---|---|---|
| **UNRESOLVED**. The mechanism applies in principle, but this environment did not produce a genuine hidden Player tab. | GAL schedules the next Player poll with chained `setTimeout(..., 1200)` only after a full frame. T2's sparse Player/continued Teacher traffic is compatible with suspension but is not diagnostic. Repeated headed attempts, including a temporary same-window profile and operator-assisted real tab selection, still reported `document.visibilityState="visible"`, `hasFocus()=true`, no `visibilitychange`, and Player poll starts every ~1207–1223 ms during the recorded 15-second cover interval. Therefore this experiment measures an automation visibility limitation, not background behavior. | Chrome documents hidden chained timers as checked once per second and intensive throttling after five hidden minutes when its other conditions hold; the official test flag shortens that grace period to 10 seconds. Chrome also documents that frozen pages suspend freezable tasks including timers and fetch callbacks. These mechanisms could create sparse polling, but no T2 browser lifecycle data exists and our test never entered hidden/frozen. | On the actual classroom device, use a supervised disposable session: record `visibilitychange`, `freeze`, `resume`, `document.wasDiscarded` and request starts; manually select another tab/minimize for over five minutes, then return. A valid test requires an observed hidden/frozen transition before interpreting request counts. |

## Decision summary

No external mechanism is established as T2's root cause. Current gateway/transit variability can add hundreds of milliseconds and occasional seconds but does not explain a two-minute absence of Player requests. Chrome throttling remains a credible but unmeasured classroom-device hypothesis. The current opt-in source trace overhead is reproducibly material in the local four-page harness, so CD recommends no release and no architecture change from this investigation.
